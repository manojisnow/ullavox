# Ullavox v1.7.0

Ullavox v1.7.0 introduces the new product identity across the application, source
repository, container image, configuration and documentation. It continues the
existing release history; earlier version tags and release artifacts remain intact.

## Changes

- Ullavox branding in navigation, onboarding, assistant labels and application status.
- Source repository: [manojisnow/ullavox](https://github.com/manojisnow/ullavox).
- Container repository: [dumanoj/ullavox](https://hub.docker.com/r/dumanoj/ullavox).
- Configuration uses `ULLAVOX_DB_PATH` and `ULLAVOX_BIND_ADDRESS`.
- Default database filename: `ullavox.db`; Compose application volume key:
  `ullavox_data`. Browser selection uses `ullavox-active-conversation`.
- Renamed container account retains numeric UID/GID `999:999`.
- CI smoke-tests the exact application image it builds.

## Fresh installation

After this release is published, install Docker and Docker Compose, then run:

```bash
curl -fsSL https://raw.githubusercontent.com/manojisnow/ullavox/v1.7.0/docker-compose.release.yml \
  -o docker-compose.ullavox.yml
docker compose -f docker-compose.ullavox.yml up -d
```

Open http://localhost:8080. The Compose file selects `dumanoj/ullavox:1.7.0`.
The default `granite4:3b` model downloads once and is cached in the model volume.
Ollama's image and model tags remain mutable. Use a trusted, single-user setup;
APIs have no authentication and published ports bind to loopback by default.

## Existing installations: explicit migration required

Read the [migration guide](https://github.com/manojisnow/ullavox/blob/v1.7.0/docs/rename-compatibility.md)
before starting the new image. Earlier environment-variable names and browser
selection keys are no longer imported automatically.

1. Record the original image, Compose project name, database filename and actual
   Docker volume names. Stop the app and back up the complete data directory with
   matching SQLite WAL/SHM files; use SQLite's backup API for a live source.
2. Pass `ULLAVOX_DB_PATH` into the new container with the actual existing database
   path. Explicitly map `ullavox_data` and `ollama_data` to the existing volumes in
   a private Compose override. Do not remove volumes or simply start against an
   empty new default path.
3. Keep the original project name where appropriate and inspect the effective
   Compose configuration before starting.
4. Verify history, preferences, projects and saved notes, then restart and verify
   persistence. Reopen the desired chat from history after the browser key change.

Stored conversation and project content is not rewritten. Numeric container
ownership remains compatible with the preceding image.

## Data handling and limitations

The existing chat, local preferences/project memory, bounded research and text-file
analysis behaviour continues. Included context goes to the selected model,
including its provider when using a cloud model. Enabled web tools send queries
and requested URLs to the configured search provider. SQLite storage is not newly
encrypted by this release. Model output and citations still require review.

## Rollback

Stop the new app and retain its data separately. Restore the consistent pre-upgrade
backup, original image and Compose configuration with the original data/model
volumes and writable numeric ownership. Keep matching database/WAL/SHM files
as a set. Do not run an older binary against an unsupported migrated database.
Changes made after the backup will not be present after restoring it.
